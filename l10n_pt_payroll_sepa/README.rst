Generate Portuguese SEPA salary payment files.

The module will turn finalized payroll runs into SEPA credit transfer
payment orders built on the posted, reconcilable net salary liabilities
of each employee, using the OCA SEPA credit transfer infrastructure
(``account_banking_sepa_credit_transfer``).

This is a draft scaffold: it declares the intended dependencies but
ships no behavior yet. The module is intentionally not installable until
the feature is implemented and its prerequisites are available.

.. IMPORTANT::
   This is an alpha version, the data model and design can change at any time without warning.
   Only for development or testing purpose, do not use in production.
   `More details on development status <https://odoo-community.org/page/development-status>`_

Configuration
=============

Planned configuration checklist. None of this is available yet; the
module ships no configuration screens.

- Install the prerequisites on Odoo 19: ``l10n_pt_payroll`` (draft, PR
  #187), ``payroll_account`` and
  ``account_banking_sepa_credit_transfer``.
- Set up a company-owned EUR debit account for salary payments and a
  dedicated SEPA payment mode for the salary run.
- Select one bank and upload channel. Use the EPC ``pain.001.001.09``
  baseline; only use ``.03`` if the bank's current guide requires or
  accepts it for that channel.
- Configure the ``SALA`` salary category purpose on the payment order
  lines. Addresses, initiating-party identifiers and batch-booking
  options are set only as the selected bank's guide requires; do not
  invent defaults.
- Ensure each salary obligation has a posted, reconcilable liability and
  an approved SEPA IBAN on the employee's effective employment version
  (``hr.version.payment_bank_account_id``).
- Restrict payroll and treasury access: salary payment orders, bank
  details and XML downloads are limited to authorized payroll and
  treasury users in the correct company.
- Gate the release on a synthetic sample file validated against the
  bank's accepted fixture or validator.

Usage
=====

Planned usage. This describes the intended flow for review; the module
does not export files yet.

1. Finalize a payroll run, then review the eligible posted salary
   payables and prepare a draft outgoing payment order with the
   dedicated salary mode, the company EUR debit account and the
   requested execution date.
2. Check the beneficiary count, total amount, debit account and
   execution date before generating the XML through the payment order.
3. Download the file and upload it manually to the bank portal, then
   authorize the payment there. Downloading does not mark anything as
   uploaded or paid.
4. Track bank rejection or acceptance separately from the payment order.
   A replacement file is created only after a rejection or a confirmed
   non-submission; never silently resend a file that might have been
   accepted.
5. Re-downloading returns the same frozen file and references. Lines
   with missing or invalid IBANs, inconsistent balances or duplicates
   are blocked for review instead of being exported.
